# 화면 상태·분기·테마 설계 v0.5 검토안

작성일: 2026-11-15 (Asia/Seoul)

고속도로 사고·고장 정차 MVP를 대상으로 한다. 기존 FigJam v0.4의 사고 접수·응답 확인(A), 대피 지원(B), 트렁크 실행 조건(C), 팀의 위험 전파·사건 종료 의견을 화면 설계에 연결한다. 화면과 분기의 설계안이며 구현 완료나 실차 안전 검증을 뜻하지 않는다.

## 1. 화면을 정하는 원칙

화면은 현재 가장 중요한 질문·행동을 크게 보여준다. 탑승자 응답, 대피, 차량 제어, 통화, 도로 위험은 각각 별도 상태로 유지한다. 하나가 완료되어도 다른 상태를 완료시키지 않는다.

| 독립적으로 유지할 상태 | 예시 |
| --- | --- |
| 응답 | 미시작 / 질문 중 / 입력 대기 / 응답 확인 / 재질문 / 응답 미확인 / 음성 경로 오류 |
| 대피 | 가능 여부 미확인 / 가능 자가 보고 / 곤란 자가 보고 / 경로 미확인 / 안내 중 / 대피 의사 / 대피 완료 보고 |
| 차량 동작 | 미요청 / 조건 확인 / 보류 / 요청 전송 / 실제 상태 확인 / 실패 / 결과 미확인 |
| 긴급 지원 | 필요 보고 / 전화 화면 연결 / 통화 중 / 통화 종료 / 접수 결과 미확인 또는 별도 확인 |
| 위험 정보 | 로컬 기록 / 전송 대기 / 서버 접수 / 유효한 사건 / 최신 상태 미확인 / 근거 있는 종료 |
| 표시 환경 | 라이트 또는 다크 / 창 크기 / 주행 UX 제한 |

화면 닫힘 ≠ 대피 완료. 트렁크 열림 ≠ 대피 완료. 서버 접수 ≠ 다른 차량 수신. 통화 연결 ≠ 구조 접수. 대피 완료 ≠ 도로 위험 해소.

## 2. 화면 상태와 전이

S1–S6은 이번 UI 논의를 위한 화면 식별자다. S6은 사고 차량의 다음 단계가 아니라 접근 차량의 독립 화면이다. 기존 와이어프레임 A0–A5/E1–E3/T1–T2/B1과의 대응을 함께 적었다.

| 화면 | 진입 조건·표시 | 다음 조건 | 기존 대응 |
| --- | --- | --- | --- |
| S1 주행·대기 | 내 위치·도로 맥락과 관련 위험. 복잡한 설정은 정차 때 제공 | 수동 사고·고장 입력 또는 검증된 자동 입력 → S2. 타 차량 사건 → S6 경고 | 기본 주행 화면 추가 |
| S2 사고·고장 접수 | 입력 출처, 위치, 비상등 상태·기본 안내. 자동 입력은 사고 의심으로 표시하고 확인 전 유형·중증도를 단정하지 않음 | 즉각 위험·긴급 도움 보고 → H. 그 외 → S3. 지원 불필요/오탐 보고는 입력 정정 경로로 기록 | A0 + v0.4 A |
| S3 응답·대피 가능 확인 | 짧은 질문 하나. 음성 상태와 화면 응답 경로. 응답자는 운전자/동승자/불명 구분 | 명확한 가능 보고 → S4. 곤란·도움 요청 → H. 침묵·불명확은 재질문 1회 후 U. 음성 경로 오류 → E | A1·A2·E1·E2 |
| S4 대피 지원 | 정차와 이동 경로 조건에 맞는 안내. 센서로 확인된 개별 차량 상태. 트렁크는 독립 동작 카드 | 정차 미확인/이동 중이면 하차·트렁크 안내 보류. 경로 불명·대피 곤란은 H. 대피 의사 또는 안내 종료 → S5 | A3 + v0.4 B·C |
| S5 지원 유지·대피 확인 | 안내를 마쳐도 대피 완료는 미확인일 수 있음. 가능한 채널에서 받은 대피 보고만 별도 기록 | 늦은 도움 요청 → H. 상태 정정 → 해당 단계 재평가. 도로 위험은 별도 유지 | A5 |
| H 긴급 도움·대피 곤란 | 실제 보고된 문제와 가능한 연락 경로를 우선 표시. 연결·통화·접수 결과를 구분 | 통화 종료 후 최신 상태로 재평가. 응답만 생겼다고 도움 요청을 자동 해제하지 않음 | A4 |
| U 응답 미확인 | 정상 음성 경로에서 재질문 후에도 응답 미확인. 의식 없음으로 표현하지 않음 | 질문 반복을 중단하고 긴급 통화 연결 지원 경로를 유지. 늦은 응답·동승자 입력은 S3/S4/H 재평가 | E1 |
| E 음성 경로 오류 | 듣기/말하기 경로 확인 불가. 응답 타이머 정지, 화면·동승자 입력과 긴급 도움 경로 제공 | 대체 입력은 S3/S4/H. 대체 입력도 미확인이면 연결 지원 유지. 복구 확인 후에만 음성 재개. 자동 반복·무응답 누적 없음 | E2 |
| S6 접근 차량 위험 경고 | 유효하고 주행 구간·방향·경로와 관련 있는 사건의 짧은 경고 | 구간 이탈은 이 차량의 해당 안내만 해제. 통신 단절·만료는 최신 상태 미확인. 유효한 종료는 해당 사건만 해제 | B1 + 팀 C·D |

오탐/지원 불필요 보고는 추가 초안이다. 반복 질문을 중단하는 것과 이미 전파된 도로 사건을 종료하는 것은 별개다. 앱 사건의 취소·종료 권한과 근거를 정하기 전에는 이 보고로 서버 사건을 자동 삭제하지 않는다.

대피 완료 입력을 받기 위해 탑승자가 차량으로 돌아오게 하지 않는다. IVI 밖에서 쓸 휴대폰·원격 채널은 후속 과제이므로, 현재 MVP는 대피 완료 미확인 상태를 정상적으로 유지할 수 있어야 한다.

## 3. 공통 분기와 동시 이벤트

1. 즉각 위험·명확한 긴급 도움 보고는 일반 질문을 중단시키고 H를 우선 표시한다. 음성·수동 입력으로 긴급 도움에 도달하는 경로를 짧게 유지한다.
2. 통화와 오디오 포커스 상실 시 앱 TTS/STT 및 응답 타이머를 멈춘다. 통화가 끝난 뒤 오디오 경로와 최신 상태를 확인해 이어간다. 긴급 통화를 앱 질문으로 끊지 않는다.
3. 정차·실행 조건이 사라지거나 오래되면 미전송 차량 명령은 보류한다. 이미 전송한 명령은 결과를 계속 확인하되 자동 재전송하거나 반대 명령을 보내지 않는다.
4. 네트워크 오류는 전파 상태 영역에 표시한다. 로컬 응답 확인·대피 안내를 가리는 전면 오류 화면으로 바꾸지 않는다.
5. 도움 요청과 다른 정상 신호가 함께 오면 도움 요청을 유지한다. 서로 다른 응답자의 보고가 충돌하면 출처와 미확인 상태를 남기고 짧게 확인한다.
6. 사고 차량의 대응 중에는 다른 사건의 반복 음성 경고가 현재 질문을 덮지 않게 한다. 위험 목록 자체는 별도로 갱신한다.

응답 대기는 질문 재생 완료와 입력 준비가 확인된 뒤 시작한다. 구체적인 대기 시간은 시연 결과로 결정하며 아직 확정하지 않는다. 오디오 오류·통화·입력 중단 시간을 무응답으로 계산하지 않는다. 늦게 도착한 과거 질문 결과는 현재 질문의 답으로 오인하지 않도록 질문 식별자·시각으로 구분한다.

팀의 “착좌 유지 + 응답 없음 + 도어 변화 없음 + 페달 조작 없음이 일정 시간 지속되면 신고” 의견은 보완 검토 항목으로 보존한다. 각 신호의 부재가 센서 미지원·관측 단절인지 실제 무변화인지 먼저 구분해야 한다. 이번 안에서는 이러한 조합을 지원 필요성 검토의 보조 정보로만 취급한다. 의식불명 판정, 자동 신고 전송, 임의의 초 단위 임계값은 확정하지 않는다.

## 4. 센서와 차량 동작의 화면 반영

입력은 값뿐 아니라 출처·관측 시각·지원 여부·현재 유효성을 함께 갖는다. 미지원, 조회 실패, 오래된 값, 아직 확인 전을 정상/꺼짐/빈 좌석으로 바꾸지 않는다. 주행 상태나 도로 방향이 불확실하면 단정적인 하차·차로·전방 거리 안내를 보류한다.

| 입력 | 화면에서 할 일 | 대신 판단하지 않을 것 |
| --- | --- | --- |
| 위치·방향·도로 매칭 | 현재 구간, 해당 경로의 위험·거리 | GPS만으로 충돌 방향·정확한 차로·안전한 탈출 경로 확정 |
| 정차·기어 등 유효한 주행 정보 | 하차·차량 동작의 조건 평가 | 브레이크가 눌렸다는 이유만으로 정차 확정 |
| 착좌·벨트·문 | 해당 좌석·부품의 확인된 상태 표시 | 의식 유무, 전원 대피 완료, 안전지대 도착 |
| 비상등·트렁크 | 요청 상태와 실제 상태를 분리 표시 | 명령 접수만으로 성공 처리 |
| 운전자 주의 경고 | 지원·의미·수신 검증 후 보조 정보로 추가 | 의료적 판정이나 사고 후 의식 정상/비정상 판단 |
| 충돌·에어백 | 실제 지원되는 입력만 사고 접수 근거로 사용 | 에어백 미전개를 경미 사고로 판단하거나 후방 추돌로 분류 |

센서 데이터는 기술 설명을 나열하는 대신 “운전석 문 열림 확인”, “트렁크 상태 확인 필요”처럼 현재 행동에 필요한 말로 보여준다. 세부 출처·시각은 진단 또는 상세 보기에 둔다. 지원하지 않는 심박·호흡 수치나 주변 차량 인지 화면을 실제 데이터처럼 그리지 않는다.

트렁크는 다음 조건을 모두 통과해야 한다: 명시적 요청 → 후방 충격·손상·공간 상태가 불명확하지 않음 → 정차·차종별 작동 조건 → SDK 지원·권한·유효 상태 → 주변 안전·최종 확인 → 닫힘 확인 → 1회 요청 → 실제 열림 확인. 이미 열렸으면 재요청하지 않는다. 후방 충격이 있거나 상태를 확인할 수 없으면 이번 흐름에서는 보류한다. 이 정책은 팀의 보수적인 설계안이며 공식적인 모든 후방 사고의 일률적 개방 금지 규정은 아니다. 확인을 위해 차 뒤로 이동하도록 요구하지 않는다.

차량 동작 결과는 “요청 중 / 상태 확인 중 / 열림 확인 / 제어 보류 / 실패 / 결과 미확인”으로 구분한다. 실패·시간 초과 뒤 자동 재시도하지 않는다. 기존 T1의 “다시 요청”은 조건 재평가와 새로운 명시적 요청을 거치도록 수정한다. 트렁크 결과를 기다리느라 대피 안내를 멈추지 않는다. 비상등도 이미 켜짐이면 중복 제어하지 않으며 제어 지원·요청·실제 상태를 구분한다.

현재 프로토타입의 차량 제어는 명시적 요청을 받은 디버그 에뮬레이터에서만 수행한다. 이 설계가 실차 자동 작동이나 제어 권한 확보를 의미하지 않는다.

## 5. 위험 전파·사건 종료

사고 차량의 응답·대피 화면과 독립적으로 사건 상태를 유지한다. 백엔드는 사건 영향 구간·방향과 차량의 수신 등록을 대조해 대상 차량에 전달한다. 최초 연결·재연결·구간/방향 변경 시 현재 구간의 유효 목록을 받는다. 앱 내부에서 다시 관련성·최신성을 확인한다.

- 구간 이탈: 그 차량에서 해당 사건 안내만 내린다.
- 통신 단절·정보 만료: 최신 상태 미확인. 사건 종료나 전방 안전으로 바꾸지 않는다.
- 유효한 빈 목록 수신: 해당 구간에 표시할 유효한 사건이 없음. 현실의 무사고를 보장하는 문구를 쓰지 않는다.
- 공공 사건 종료: 제공기관의 유효한 종료 갱신을 확인한 사건만 종료한다. 다른 활성 사건은 유지한다.
- 앱 등록 사건 종료: 해제 주체·근거·오탐 정정 정책이 아직 미정이다. 대피·이탈·통신 단절·만료만으로 종료하지 않는다.

## 6. 라이트·다크 모드

설정은 “시스템 설정 따르기(기본) / 라이트 / 다크”로 제안한다. 자동 모드는 플랫폼이 제공하는 테마 상태를 따르며, 앱이 시각·헤드라이트·조도만으로 별도 야간 판정을 만들지 않는다. 차량별 테마 신호 반영은 에뮬레이터에서 확인한다. 사용자 설정 변경은 정차 상태에서 제공한다.

| 역할 | 라이트 | 다크 | 공통 규칙 |
| --- | --- | --- | --- |
| 기본 배경·패널 | 밝은 중립 배경과 구분되는 패널 | 낮은 밝기의 중립 배경과 구분되는 패널 | 정보 계층·배치 동일 |
| 본문·아이콘 | 어두운 전경 | 밝은 전경 | 텍스트와 아이콘으로 의미 전달 |
| 진행·선택 | 테마에 맞는 파랑 계열 | 테마에 맞는 파랑 계열 | 정상 진행이며 안전 보장을 뜻하지 않음 |
| 주의·미확인 | 읽기 쉬운 황색/주황 계열 강조 | 눈부심을 줄인 황색/주황 계열 강조 | 사유와 다음 행동 표시 |
| 긴급·오류 | 빨강 계열 강조 | 빨강 계열 강조 | 색만으로 구분하지 않음; 두 의미는 문구·아이콘으로 구분 |
| 개별 상태 확인 | 초록 계열의 작은 상태 표시 | 초록 계열의 작은 상태 표시 | 확인된 사실만 표시. 차량 전체·도로 전체 안전 완료로 표현하지 않음 |

같은 화면·같은 상태를 두 테마로 표현한다. 지도·차량 그림·버튼·대화상자·로딩·오류·시작 화면까지 일관되게 적용하고, 플랫폼이 소유하는 화면은 플랫폼 설정에 따른다. 좁은 창에서는 보조 지도·차량 그림을 줄이고 현재 질문과 주요 행동을 남긴다. 주행 UX 제한은 테마와 무관하게 적용한다.

테마 전환은 응답 횟수·타이머·진행 상태·통화 상태·차량 명령·사건 등록에 영향을 주지 않아야 한다. 화면 재생성으로 질문을 반복하거나 트렁크 요청·위험 사건 등록을 다시 보내면 실패다. 진행 중 입력을 보존하고, 경로가 끊겼다면 음성 오류/재연결 상태로 명시하며 무응답으로 처리하지 않는다.

## 7. 검증 수준과 시연 기준

확인 수준을 “공식 API/문서 확인”, “에뮬레이터 실제 수신 확인”, “샘플 입력 시연”으로 구분한다. 개발용 진단 화면과 발표 자료에서 명확히 밝힌다. 일반 제품 화면에는 사용자에게 필요한 “확인됨 / 확인 필요 / 사용할 수 없음”을 표시한다.

현재: 착좌·벨트·브레이크 API 존재 확인, 실제 수신은 별도 검증. DRIVER_ATTENTION 타입과 경고 API 확인, 실제 지원·의미 미확인. 심박·호흡 공개 API 미확인. 현재 에뮬레이터의 에어백 전개 속성 미지원 이력. 후방 충돌 자동 분류·사고에서 Gleo의 선제 대화 시작·앱 자동 표시·백그라운드 지속 감시는 검증 완료 기능으로 제시하지 않는다.

두 테마 각각에서 다음 경로를 확인한다.

| 시나리오 | 통과 기준 |
| --- | --- |
| 응답 있음·대피 가능 | 정차·경로 조건에 맞는 S4. 별도 차량 동작을 기다리지 않음 |
| 후방 충돌 보고·상태 불명 | 트렁크 보류 사유 표시, 대피·도움 경로 유지 |
| 정상 음성 경로에서 무응답 | 재질문 1회 후 U. 의식 없음으로 표시하지 않음 |
| TTS/STT 오류 | E. 무응답 누적 없음, 대체 입력 가능 |
| 긴급 도움·통화 | H 우선. 앱 음성 중단, 통화 종료 후 상태 재평가 |
| 센서 미지원·오래됨·값 충돌 | 미확인 유지. 잘못된 완료·정차·안전 판정 없음 |
| 요청 성공 응답만 있고 실제 열림 없음 | 결과 미확인 유지. 자동 재요청 없음 |
| 대피 의사 또는 화면 닫힘 | S5 대피 완료 미확인. 도로 사건 유지 |
| 통신 단절·재연결 | 로컬 지원 유지, 전파 미확인 및 현재 구간 목록 동기화 |
| 사건 여러 개 중 하나 종료 | 종료된 사건만 제거 |
| 질문·차량 요청 중 테마 변경·창 크기 변경 | 입력·재질문 횟수·사건 유지, 제어·등록·음성 중복 실행 없음 |
| 미지원 자동 진입 경로 | 수동/샘플 시연임을 명시하고 실제 자동 감지처럼 주장하지 않음 |
