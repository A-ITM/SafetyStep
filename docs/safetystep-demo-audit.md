# 세이프티스탭 시연 동작 검수

검수일: 2026-11-15 KST. 설치 앱 0.3.1-safetystep, Pleos flavor, Vehicle SDK 2.3.2, Pleos Connect 2.1 / Android 34 에뮬레이터.

차량 상태와 앱을 함께 보여주는 시연은 가능하다. 문 개방 입력은 좌측 기본 차량 그림과 우측 앱에 반영되고, 앱의 트렁크 요청도 SDK를 거쳐 실제 에뮬레이터 차량을 연다. 다만 현재 버전은 버튼으로 분기를 검증하는 단계이며, 실제 음성 대화와 차량 상태로 자연스럽게 진행되는 시연에는 보완이 필요하다.

이번 검수는 설치된 앱 동작과 소스를 대상으로 했다. 제품 코드와 APK는 수정하지 않았다.

## 우선 수정할 문제

| 우선순위 | 발견 사항 | 시연에 미치는 영향 | 수정 방향 |
| --- | --- | --- | --- |
| 높음 | 착좌 의미가 뒤집혀 전달됨 | 콘솔 Occupied → 원시값 2 → SDK false, Empty → 원시값 1 → SDK true. 하차 판정에 사용하면 잘못된 결론 | SDK/Vehicle Service의 변환 계약 확인. 해결 전에는 착좌 미확인으로 취급. 원시 UNKNOWN까지 false로 축약되므로 단순 Boolean 반전은 피함 |
| 높음 | 주행 중 패널 차단 | 접근 차량 경고 화면에서 D·20 km/h 입력 시 ‘주행 중에는 사용할 수 없습니다’ 표시 | 주행 경고 화면을 별도로 설계하고 CarUxRestrictions 연동 및 플랫폼 요건 검증 |
| 높음 | 응답 화면에 실제 음성 입력 미연결 | 파형은 정적 그림, 15초 타이머는 화면 시연. 응답/이동 가능 여부는 버튼으로만 진행 | 기존 TTS/STT 진단 경로를 제품 상태 전이에 연결. Gleo 실행 경로는 별도 검증하고 실제 연결 전에는 시연 입력임을 표시 |
| 중간 | 확인 문구가 터치되지 않음 | 문구 중앙을 눌러도 체크되지 않음. 작은 사각형만 눌러야 함 | 확인 행 전체를 하나의 선택 영역으로 만들고 접근성 역할/상태도 통합 |
| 중간 | 보조 조작과 확인 팝업이 작음 | 큰 주 버튼과 달리 트렁크 요청·팝업 확인은 높이 48dp | 핵심 조작 영역을 80dp 이상으로 통일하고 긴급 도움 경로도 큰 영역 확보 |
| 중간 | 상태 변화가 다음 단계로 연결되지 않음 | 문을 열거나 좌석 입력을 바꿔도 준비 화면에 머묾. 기본 경로 8번, 선택적 트렁크 포함 10번 터치 | 신호로 확인할 사실은 자동 갱신하고 사람만 판단할 항목에 응답을 요청. 비탑승을 안전지대 대피 완료로 단정하지 않음 |
| 중간 | 센서/통신 갱신이 전면 생명주기에 종속 | 차량 조회는 약 5초 간격이며 앱이 비활성화되면 조회 작업 중단 | 시연에서 다른 패널을 조작하거나 Gleo가 전면에 뜰 때의 지속성 시험, 적절한 관찰·상태 보존 구조 검토 |

주행 제한을 단순히 해제하는 방식으로 처리하지 않는다. Pleos는 CarUxRestrictions의 변경을 수신하고 제한 항목별로 UX를 적용하도록 안내한다. [Pleos 주행 규제 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

## 실제 패널 터치 검수

화면은 2560×1440 / density 160, 앱 창은 우측 841×1210이다. 아래 값은 Compose 소스와 UIAutomator의 실제 클릭 영역을 대조했다. 이 에뮬레이터에서는 1px=1dp이며, 실제 차량 패널에서 팔을 뻗는 거리나 진동까지 검증한 것은 아니다.

| 조작 | 현재 클릭 영역 | 평가 |
| --- | --- | --- |
| 주 동작 버튼 | 폭 745 × 높이 108dp | 충분한 크기 |
| 보조 큰 버튼 | 높이 104dp | 충분한 크기 |
| 사고 유형 | 높이 92dp | 충분한 크기 |
| 정차/이동 경로 체크 | 56×56dp | 문구/나머지 행은 반응하지 않음. 실제 터치 실패 재현 |
| 트렁크 열기 요청 | 116×48dp | 작은 조작 영역 |
| 트렁크 최종 확인 | 166×48dp | 팝업에서 갑자기 모바일 크기로 축소 |
| 긴급 도움 링크 | 높이 64dp | 긴급 상황의 대체 경로로는 확대 권장 |
| 더 보기 | 약 65×64dp | 주행/긴급 핵심 조작은 이 메뉴에 두지 않기 |

차량용 크기 비교에는 Google의 76×76dp 가이드를 참고했다. [Android Automotive 터치 영역 가이드](https://developers.google.com/cars/design/automotive-os/design-system/sizing)

기본 정차 흐름은 현재 크기에서 필수 조작이 보인다. 창을 넓히면 portrait 고정 때문에 좌우 검은 여백이 생기는 현상도 관측했다. 촬영은 두 앱 창을 나눈 상태에서 좌측 기본 차량 / 중앙 기본 내비 / 우측 세이프티스탭으로 맞춰야 한다. 내비의 지도 타일은 현재 표시되지 않고 검색 결과·경로 카드만 보여 별도의 환경 확인이 필요하다.

## 차량 데이터 주입 결과

Virtual Console의 실제 설치 HTML과 /vehicle/catalog에 나온 입력을 사용했다. 콘솔 세션이 비활성화되면 503이 발생하여 시험 중에는 세션 heartbeat를 유지했다. SDK 검증은 설치된 androidTest의 probeInstalledVehicleServiceWithoutSilentFallback을 사용했다.

| 입력 | 앱 SDK 결과 | 기본 차량 화면 / 제품 UI |
| --- | --- | --- |
| 운전석 문 열기/닫기 | true / false 확인 | 좌측 문 애니메이션과 우측 ‘문 열림/닫힘’ 모두 반영 |
| 트렁크 열기/닫기 | GET 100 / 0 확인 | 좌측 개방 모습·차량 경고 반영 |
| 제품 UI에서 트렁크 요청 | 닫힘 확인 후 SDK 요청, 열림 확인 문구 | 좌측 실제 트렁크가 열림. 70초 영상에 포함 |
| 운전석 Occupied / Empty | raw 2 → false / raw 1 → true | 현재 착좌 해석 실패. 제품 UI에는 착좌 표시 자체도 없음 |
| 브레이크 50% / 0% | true / false 확인 | 제품 화면에 표시/흐름 연결은 없음 |
| 벨트 | 현재 false 읽기 확인 | 체결 true 주입은 이번에 검증하지 못함. Telltales의 SeatBelt 경고등 조작을 벨트 체결 데이터로 대체하면 안 됨 |
| 에어백 전개 | ERROR_NOT_SUPPORTED_PROPERTY 재확인 | 실제 전개 신호에 의한 자동 시작 시연 불가 |
| D / 20 km/h | 기본 화면의 D·20 표시 | 세이프티스탭은 시스템 차단 화면으로 대체됨 |

좌측 기본 화면은 문·트렁크를 시각화하는 데 활용할 수 있다. 운전석 착좌 여부를 별도 인물이나 좌석 색으로 표시하는 기능은 이번 시험에서 확인되지 않았다. 제품에서 필요한 착좌 정보는 의미를 바로잡은 뒤 우측 맥락 정보로 제공해야 한다.

착좌 불일치는 단순 전송 실패가 아니다. 로그에서 SEAT_OCCUPANCY의 운전석 area 1에 값 2와 1이 각각 도착했다. 설치된 SDK 2.3.2의 getCurrentSeatOccupancy 콜백 변환은 정수 1만 true로 반환한다. AOSP 표준은 UNKNOWN=0, VACANT=1, OCCUPIED=2이므로 현재 에뮬레이터·SDK 조합에서는 ‘탑승 여부’라는 앱 변수 의미와 맞지 않는다. [AOSP 좌석 점유 상태 정의](https://android.googlesource.com/platform/packages/services/Car/+/master/car-lib/src/android/car/VehicleSeatOccupancyState.java)

SDK 조회 테스트가 두 번 성공했다는 것은 API 호출 완료를 의미한다. 기존 probe 테스트는 탑승 입력과 반환 의미가 일치하는지 검증하지 않으므로, 그 통과만으로 착좌 정상 동작을 주장할 수 없다.

## 권장 시연 구성

외부 콘솔에서 시나리오를 재생하고 차량 화면에는 실제 서비스 조작만 남기는 구성이 적합하다.

1. 운영자 콘솔에서 사고/고장 시나리오를 시작한다. 현재 전개 신호가 미지원이므로 사고 트리거 주입임을 명시한다. 제품의 시나리오 선택 버튼은 운영자 영역으로 옮긴다.
2. 앱이 질문을 재생하고 운전자/동승자의 실제 응답으로 역할과 도움 필요 여부를 갱신한다. 버튼은 음성이 어려울 때의 대체 수단으로 유지한다.
3. 정차 정보는 검증된 차량 신호로 표시한다. 안전한 이동 경로, 이동 가능 여부, 트렁크 개방 의사는 사용자 응답을 받는다. 기어 P만으로 주변 안전까지 판단하지 않는다.
4. 비후방 상황에서 명시적 요청과 조건 확인 후 트렁크를 제어한다. 좌측 기본 차량의 개방 애니메이션과 우측 SDK 확인 결과를 함께 보여준다. 후방 충돌은 요청 보류 분기를 보여준다.
5. 콘솔의 문·착좌 시나리오가 앱의 관측 상태를 바꾼다. 착좌 해석 수정 전에는 ‘하차 감지’ 완료 연출에 사용하지 않는다. 수정 후에도 빈 좌석은 안전지대 대피 완료의 증거로 취급하지 않는다.
6. 후속 지원에서 도로 위험은 유지한다. 접근 차량 시연은 주행 제한 대응을 완료한 후 별도 수신 화면으로 연결한다.

현재 정상 경로의 터치는 지원 시작 → 사고 유형 → 응답 시작 → 응답자 → 이동 가능 → 정차 확인 → 경로 확인 → 안내 종료의 8회다. 트렁크를 요청하면 두 번이 추가된다. 화면 수를 무조건 줄이기보다 ‘신호로 확인할 사실’과 ‘사람에게 물어야 할 판단’을 분리하는 것이 먼저다.

콘솔 준비는 `adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088/`를 열고 활성 상태를 확인한다. 문·착좌 값은 Emulation Controls의 Door Position / Seat Occupancy에서 바꿀 수 있다. [Pleos Virtual Console 가이드](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)

반복 촬영에서는 상태 입력 직후 세션을 닫지 말고 SDK/기본 차량 화면에서 실제 반영까지 확인해야 한다. 이번에도 최초 원복 직후에는 이전 트렁크 상태가 남아 추가 확인·닫힘 입력을 거쳤다. 백엔드 전파와 실차 센서 정확도, 실제 발화, 긴급 통화는 이번 검수 범위에 포함하지 않았다.
