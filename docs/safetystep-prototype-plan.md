# 세이프티스탭 프로토타입 구현·검수 계획

> 최신 계획은 [자동 대응 계획](safetystep-automatic-plan.md)이다. 아래는 이전 구현 기록이다.

2026-11-15 · 제품명: 세이프티스탭 / SafetyStep

## 목표

기존 Android/Jetpack Compose 기술 프로토타입을 세이프티스탭 우측 앱 패널로 구성한다. 기본 차량 상태·내비게이션은 Pleos 창을 사용하며, 앱은 질문과 행동, 탑승자·도로 위험 상태에 집중한다. 기능 기준은 `ui-state-and-theme-spec.md` v0.5, 시각 기준은 사용자가 제공한 Figma S1·S2P·S4·S6 프레임이다.

## 작업 순서

1. 계획 검수: 기존 분기와 구현 범위를 대조하고 데이터·실행 경계를 확정한다.
2. 상태 로직: 응답·대피·차량 제어·통화를 구분하고 센서 미확인과 조건 보류를 처리한다.
3. UI: 세이프티스탭 브랜딩, 공통 라이트/다크 색상, 주행·사고·응답·대피·도움·접근 경고 화면을 구현한다.
4. 연동: VehicleGateway의 실제 조회와 기존 로컬 사건 전파를 재사용하고 진단·시나리오 조작은 별도 패널로 옮긴다.
5. 검수: 단위 테스트, 두 flavor의 빌드·lint, 에뮬레이터 UI 테스트와 화면 캡처를 확인하고 발견 사항을 수정한다.

## 구현 범위

- 브랜드·앱 표시명: 세이프티스탭. 패키지 ID와 기존 연동 계약은 유지.
- 테마: 시스템 / 라이트 / 다크. 동일 화면과 동일 행동, 테마 선택 저장.
- 기본 화면: 실제 Pleos 내비게이션 옆 단일 창에서 지원 대기와 사고·고장 지원 시작. 앱 내부 지도·주행 계기 재현 없음.
- 사고 대응: 충돌 정보 입력, 응답자 확인, 대피 가능 여부, 음성 오류/응답 미확인, 대피 안내와 안내 종료, 긴급 연락 과정 시연.
- 센서: 지원되는 기어·문·트렁크·착좌·벨트·페달 상태를 조회하고 출처·미확인을 유지. Pleos에서 실패를 샘플 값으로 대체하지 않음.
- 트렁크: 후방 사고/불명·정차/주변 조건 미확인에서 보류. 최종 명시적 확인 후 에뮬레이터 명령 1회, 실제 결과와 요청을 구분.
- 접근 경고: 기존 로컬 HTTP 수신과 시연 시나리오. 전파 중단·위치 만료·다른 도로·다른 방향·통과를 구분.
- 검증 조작과 기존 SDK·Gleo 진단은 별도 진단 화면에서 접근.

## 계획 검수 결과

| 점검 | 결정 |
| --- | --- |
| 실제 도로·주변 차량 인지로 오인 가능성 | 지도는 기본 내비게이션 창에 맡김. 우리 앱의 위험 거리·좌표는 시연 값으로 표시 |
| Gleo·마이크 자동 동작 | 미검증 선제 대화를 구현 완료로 표시하지 않음. 이번 UI는 화면 응답과 명시적 음성 경로 시연 사용; 기존 실제 음성 진단 유지 |
| 무응답과 음성 오류 | 별도 분기. 재질문 1회. 음성 실패는 무응답으로 누적하지 않음 |
| 대피 후 IVI 조작 요구 | 안내 종료와 대피 완료를 분리. 차량 복귀를 요구하지 않음 |
| 차량 제어 | 기존 debug 에뮬레이터 제한 + 신규 상황 조건. 물리 차량 제어 없음 |
| 긴급 신고 | 실제 신고·통화 없이 연결 과정 시연임을 표시 |
| 서버 영향 구간 필터링 | 기존 HTTP 전달의 현재 구현 수준을 보존·표시. 이번 UI 변경을 서버 구간 구독 완성으로 주장하지 않음 |
| 사건 종료 | 테스트 해제는 진단에만 유지. 대피·테마·창 닫기로 사건을 끝내지 않음 |
| 테마 변경 | 상태와 효과 실행을 분리. 화면 재구성으로 사건 생성·질문·제어를 재실행하지 않음 |

## 완료 기준

- 정상 응답, 도움 요청, 무응답, 음성 오류, 후방 추돌, 트렁크 보류/결과 미확인, 대피 안내 종료 경로가 검증된다.
- 라이트·다크에서 텍스트·버튼·상태를 읽을 수 있고, 주요 행동이 화면 밖으로 잘리지 않는다.
- 테마 변경과 Activity 재생성에서 사건·응답·대피 상태를 보존하고 차량 명령이 중복되지 않는다.
- `./scripts/check-android.sh` 통과 및 에뮬레이터에서 주요 화면·상호작용 확인.
- 검수 기록에 통과 항목, 실제 SDK 조회 결과, 남은 제약과 화면 캡처를 기록한다.

사용자가 제공한 `QuiuuWbKFqSNjSHQmOKIOX` 파일의 S1(1:518), S2P(1:655), S4(1:812), S6(1:1018) 및 내부 앱 프레임을 확인했다. 앱 내부에서 차량 계기 영역과 지도까지 다시 그린 초기 배치는 폐기한다.
