# 세이프티스탭 프로토타입 검수 기록

2026-11-15 · Android `0.3.1-safetystep` · 계획 → 구현 → 실행 검수 완료

## 완성 범위

사용자가 제공한 Figma 파일의 S1·S2P·S4·S6를 확인하고 초기 배치를 수정했다. 앱 내부에 만들었던 차량 상태 패널과 지도 도식을 제거했다. Pleos의 기본 Driving view와 내비게이션은 별도 시스템/앱 창으로 두고, 세이프티스탭은 우측 portrait 창 하나에 질문·행동·상태만 표시한다. 테마·시연·진단은 상단 더보기 메뉴로 이동했다.

참고: [Figma S2P](https://www.figma.com/design/QuiuuWbKFqSNjSHQmOKIOX/Untitled--Copy-?node-id=1-655), [Pleos 창 정책](https://document.pleos.ai/en/docs/connect/guide/docs-design/getting-started/window), [앱 구조 및 동작 모델](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model).

- 시스템/라이트/다크 테마 선택과 저장. 테마 전환은 사건·응답·대피 상태나 명령 실행을 새로 만들지 않는다.
- 주행 대기 → 사고 상황 → 운전자/동승자 응답 → 이동 가능 여부 → 대피 안내 또는 도움 요청.
- 음성 경로 오류와 응답 미확인을 구분. 응답 대기 15초와 재질문 1회는 명시적 화면 시연이다.
- 후방 충돌·충격 여부 미확인·정차 미확인·P 기어 미확인·트렁크 상태 미확인에서는 열기 보류.
- 조건 확인 후에도 최신 센서와 지원 상태를 다시 검사. 이미 열렸으면 중복 요청하지 않고, 실패 시 자동 재시도하지 않는다.
- 대피 안내 종료, 실제 대피 보고, 도로 위험 종료를 독립 상태로 유지.
- 접근 차량의 샘플 위험 경고와 기존 로컬 HTTP 사건 수신. 통신 단절·위치 만료 시 최신 상태 미확인 표시.
- 진단 화면과 시연 도구 분리. 실제 SDK 조회와 샘플 값의 출처 표시.

## 검수 환경과 결과

Pleos 2.1 / Android 14(API 34) / arm64 / emulator-5554 사용자 10. 전체 디스플레이 2560×1440, 수정 후 단일 앱 창 841×1210. 기본 내비게이션은 중앙 창, 세이프티스탭은 우측 창으로 시스템 window bar에서 배치했다. 창 위치는 앱이 강제로 점유하는 것이 아니라 Pleos의 창 정책과 사용자 조작으로 결정된다. Host Homebrew JDK 17, `GRADLE_USER_HOME=$HOME/.gradle` 사용.

실행 테스트는 화면 버튼으로 경로를 이동하고 테마 변경과 Activity 재생성 이후 같은 사건 ID·위험 상태·제어 횟수가 유지되는지 검사했다. 후방 충돌 시 제어 시도 0회, 대피 안내 종료 후 `evacuated=false`와 `hazard=ACTIVE`, 음성 오류와 무응답의 별도 상태, 연락 시연 시 타이머 중단, 오프라인/반대 방향 경고 분리, 로컬 HTTP 사건 등록·중복·종료 갱신을 확인했다.

샘플 트렁크 제어는 Demo flavor에서만 실행했다. 이번 검수에서 Pleos SDK를 통한 트렁크 SET은 실행하지 않았다. 실제 Pleos 제어는 기존 debug 에뮬레이터 제한을 유지하고, 명령 전 닫힘 확인과 최종 상태 재검사를 추가했다. 그 경로의 이번 근거는 빌드와 조건 테스트이며 실차 동작 검증은 아니다.

참고 프레임의 단일 패널 구성에 맞춰 헤드라인 54sp, 본문 28sp, 주요 버튼 높이 108dp/글자 30sp로 조정했다. 두 테마의 실제 단일 창 캡처에서 주요 문구와 버튼, 하단 상태가 겹치지 않는지 확인했다. 다른 디스플레이 크기 및 차량용 사용성 인증은 이번 검수 범위가 아니다.

## 남은 연동 범위

- 이번 제품 화면은 버튼 응답 시연이다. 기존 실제 음성 진단은 유지했지만 제품 화면의 자동 마이크 시작·Gleo 선제 대화·사고 자동 기동은 연결 완료로 주장하지 않는다.
- 앱 내부 지도 도식은 삭제했다. 기본 내비게이션 앱과의 동시 배치를 확인했으나 해당 내비게이션의 지도 타일은 현재 에뮬레이터에서 비어 있다. 이를 대체하는 가짜 지도를 그리지 않았다.
- 우리 경고의 좌표·400m 거리는 시연 값이다. 기본 내비게이션의 실제 경로를 우리 앱과 연동하거나, 공공 교통정보·서버 구간별 전파 구독을 완성한 것은 아니다.
- 긴급 통화는 과정 시연이며 실제 전화·구조 요청을 보내지 않는다.
- 생체신호·DMS, 센서 변화의 전체 구독, 여러 실차 디스플레이 및 실차 작동은 미검증이다.
- 배경 진입 시 질문 타이머를 중단하고 복귀 시 남은 시간을 이어 간다. 프로세스 재시작 시 제어 조건 동의는 복원하지 않고, 진행 중이던 제어 결과는 미확인으로 복원한다. 무인 백그라운드 감지 완성을 의미하지 않는다.

## 실행 방법

현재 에뮬레이터에 `세이프티스탭`(Pleos SDK)과 `세이프티스탭 Demo`(샘플)를 설치했다. 초기 화면의 **사고·고장 지원 시작**으로 정상 흐름을 따라갈 수 있다. 상단 **•••**에서 테마, 새 시연, 음성 오류, 무응답, 접근 방향·통신 상태를 선택한다. 같은 메뉴의 **SDK·음성 진단 열기**에 기존 점검 기능을 유지했다.

내비게이션이 앱 영역 전체로 확장되어 있으면 시스템 우측 window bar를 중앙으로 이동해 1:1로 나눈다. 이번 에뮬레이터에서 오른쪽 핸들을 `2546,720 → 1700,720`으로 드래그한 후 기본 내비게이션과 세이프티스탭이 나란히 나타나는 것을 확인했다. 1:1 상태에서 가운데 핸들 `1706,720`을 탭하면 두 앱의 좌우 위치가 교환되는 것도 확인했다. 좌우 위치와 핸들 위치는 현재 시스템 창 구성에 따라 달라진다.

로컬 HTTP 전파 시연이 필요하면 저장소에서 `./scripts/run-prototype-server.sh`를 실행하고 `adb reverse tcp:8787 tcp:8787`을 적용한다. 이번 검수에서는 로컬 서버를 실행하고 연결했다. UI 샘플 시연은 서버 없이도 가능하다.

## 산출물과 근거

모든 산출물은 로컬에 저장했다. 작업 폴더는 `<로컬 작업 폴더>/output/safetystep/`이다.

- `SafetyStep-pleos-debug.apk`, `SafetyStep-demo-debug.apk`
- `verification.json`: APK SHA-256, 테스트 수와 제외 항목
- `revised/build.log`, `revised/demo-instrumentation.log`, `revised/pleos-instrumentation.log`: 배치 수정 후 최종 검수
- `revised/pleos/sdk-probe.json`, `revised/demo/sdk-probe.json`: SDK/샘플 출처와 조회 원문
- `revised/pleos/`: 주요 화면 PNG 14개. `revised/demo/`: 샘플 제어 결과를 포함한 PNG 15개.
- `revised/native-*.png`: 실제 차량 화면·내비게이션·우측 앱 동시 배치 캡처.
- 상위 폴더의 기존 화면 PNG는 수정 전 비교 자료이며 최종 디자인이 아니다.

에뮬레이터의 내부 시간과 호스트 시간이 다르므로 원시 SDK 기록의 epoch 값은 실행 당시 에뮬레이터 시계 값이다. 보고서 날짜는 호스트 기준이다. 기존 작업 변경을 보존했으며 Git 커밋·푸시는 하지 않았다.
