## 범위와 실행 환경

이번 완료 기준은 [0.6 계획](safetystep-prototype-v06-plan.md)과 [공통 계약](contracts/prototype-v06.md)이다. 장기 계획 1.3 전체를 구현한 것으로 판정하지 않는다. 문서 검수 5회와 지적 수정 재확인을 먼저 완료한 뒤, gpt-6.1-sol xhigh 작업자 3명이 Android 흐름/전송, 서버, 음성/위치/UI를 분담했다. 주관자가 공통 계약·통합 시험·코드 리뷰·GitHub 작업을 담당한다.

- Pleos Connect 2.1 AVD / Android 14 arm64 / `ranchu` / 사용자 10.
- 실제 설치·제어 대상은 명시적 `emulator-5554`만 사용. 연결된 개인 휴대폰에는 설치·제어하지 않음.
- 기존 JDK 17, 호스트 `~/.gradle`, 기존 Android SDK/AVD 재사용.
- local Deno HTTP, TEST 도로·위치. 운영 인증·공공 돌발정보·실제 도로 판정·비전면 자동 기동은 범위 밖.
- 실제 Pleos TTS/STT 시험과 demo의 음성 미지원 결과를 구분. 합성 PCM 시험은 사람의 마이크 시험이 아님.

분포·95백분위·실제 운전자 반응 효과를 증명한 값은 아니다. 무응답 후보 경로는 대피 안내를 자동 시작하지 않고 정차 위험을 공유하므로 이 경로에는 N을 붙이지 않는다. 공공 원천과의 도달 시간 차이 Δ는 공공 연동이 없어 측정하지 않았다.

## 로컬 계측 해석

`files/prototype-metrics.jsonl`의 UTC·단조 시각과 사건 ID를 사용한다. 원음·대화 원문을 측정 파일에 저장하지 않는다. 최초 정차→공유→수신(H), 지원 입력→실제 TTS 시작/완료(N), 실제 TEST 위치 통과→경고 완료(Y)를 별도로 계산한다. 동일 AVD 부팅에서 얻은 단조 시각만 직접 비교한다. 조회 요청 시각을 새 위치 관측 시각으로 바꾸지 않는다.

`scripts/verify-prototype-v06.py`는 명시적 에뮬레이터를 검사한 뒤 기존 Virtual Console HTTP 인터페이스를 사용한다. 로컬 `output/`에 TEST 상태·화면·계측 결과와 부팅 식별자를 저장한다. 파일은 Git과 원격 ChatGPT 저장소에 올리지 않는다.

## 구현 중 발견·수정한 사항

- 서버 enum 검증에서 문자열 강제 변환이 배열 값을 허용할 수 있는 지점을 발견해 엄격한 형식 검사와 회귀 시험을 요구했다.
- Android wire 문자열도 플랫폼 JSON 변환 차이로 잘못된 타입을 받아들이지 않도록 명시적 타입 검증을 요구했다.
- 안내 완료·실제 TTS 시작, 무응답·음성 오류, 수신 설정·실제 수신 상태를 각각 구분한다.
- 관측 좌석 비움 뒤 버튼 조작을 요구하지 않으며, 이미 저장된 도움 필요 상태는 도로 사건 종료나 좌석 변화로 지우지 않는다.

- 동의 OFF/ON 대기 명령, 실제 HTTP 단일 요청 유지, 생성의 원자 저장, 같은 버전의 불변 필드, 오래된 세대의 음성 취소를 독립 리뷰 후 수정했다.
- 정확한 도움 발화 `도와줘`/`살려줘`와 부정 표현 회귀 시험을 추가했다.
- 도움 화면의 신고 위치가 전화 버튼보다 아래에 가려지는 문제를 발견해 위치→전화 순서로 바꾸고 실제 우측 패널에서 확인했다.
- 최종 PR 리뷰에서 Gleo 시작 콜백·스키마에 남은 질문 우선 표현을 발견해 로컬 지원 접수와 정차 관측 조건에 맞췄다. 이 수정은 실제 Gleo 자동 기동 검증을 뜻하지 않는다.
- 첫 빌드는 과거 자동 트렁크 동작을 기대하던 시험 1개가 실패했다. 새 범위에 맞춰 자동 제어 없음의 회귀 시험으로 바꾸고 최종 검사를 통과했다.
- 초기 연속 QA는 오래된 `operator-state.json`의 visible 값만 보고 앱 시작 완료를 오인했다. 새 heartbeat까지 기다리고 reset/동의를 관측하는 방식으로 고쳤다. 실패를 앱 공유 성공으로 집계하지 않았다.

## 재현 명령과 남은 범위

```sh
./scripts/check-android.sh assembleDemoDebugAndroidTest assemblePleosDebugAndroidTest
python3 scripts/smoke-prototype.py --output output/http-smoke.json
python3 scripts/verify-prototype-v06.py --serial emulator-5554 --phase all --output output/v06-flow
```

HTTP smoke 이후 연속 앱 시험 전에는 서버를 재시작해 이전 시험 사건을 비운다. 앱 시험은 설치된 두 debug APK·실행 중인 8787 서버·Pleos Virtual Console 8088을 사용한다. 스크립트가 해당 에뮬레이터에 포트 연결을 설정한다. 실제 음성 계측 시험은 `response-test.pcm` 합성 음성 fixture를 별도 준비해야 한다.

첫 안내와 접근 경고의 실제 음성, NaviHelper 현재 위치, 차량 좌석 조회는 확인했다. 실제 충돌/에어백에 의한 기동, Gleo 선제 호출, 백그라운드 실행, 사람 마이크 재시험, 운영 Auth/DB/공공 정보, 물리 차량 제어는 이번 검증 결과에 포함하지 않는다. 위험 전파 위치는 TEST이며 보고용 Navi 좌표와 독립이다. 잔류 좌석은 화면으로 알리며 별도의 반복 음성 알림·감속 재경고는 후속 검토 대상이다.

이번 로컬 판정은 0.6 개발 프로토타입 범위의 통과다. 실도로 안전 효과나 배포 준비 완료를 뜻하지 않는다.
