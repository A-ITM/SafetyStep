# 세이프티스탭 0.4.0 구현·검수

2026-11-15 KST. Pleos Connect 2.1 / Android 34, Vehicle SDK 2.3.2, Pleos TTS/STT 3.3.1. 앱 패널은 841×1210dp이며 기본 차량 화면·내비는 Pleos가 제공한다. 로컬 변경이며 커밋·푸시는 하지 않았다.

## 제품 화면

기존 Figma의 우측 패널 색·여백·큰 제목 구조를 유지했다. 공통 토큰으로 48dp 외곽 여백, 제목 54/70sp, 설명 28/40sp, 동작 30/40sp, 상태 24/34sp와 라이트·다크 의미 색을 적용했다. Figma 변수 조회는 빈 결과였으므로 원격 변수 자동 연결을 주장하지 않는다.

- 제목·단계·상태·행동의 위계를 분리하고 시작선을 통일했다. 단계는 왼쪽, 사고 맥락은 오른쪽에 정렬했다.
- 대피 준비는 차량 상태 세 칸 → 이동 전 확인 두 행 → 선택적 트렁크 → 주 행동 순서다. 주요 버튼 112dp, 보조 버튼 104dp, 기타 조작 최소 80dp를 사용한다.
- 확인 행 전체가 체크 동작과 접근성 역할을 가진다. 문장 중앙·오른쪽 끝 터치도 검사했다. 트렁크 확인 팝업도 같은 큰 버튼을 사용한다.
- 제품 화면에서 ‘시연’, ‘대피 완료 미확인’ 등 개발 설명을 제거했다. 입력 출처와 SDK 한계는 외부 검증 화면·기술 진단에 둔다. 상태 모델에서 대피 완료를 자동 확정하는 변경은 하지 않았다.
- 실제 응답 화면은 Pleos TTS 완료 → STT 결과 → 분기로 연결한다. 연결 실패/무응답/중단/최종 인식 결과를 분리하며 취소한 질문의 늦은 콜백을 차단한다. 실제 듣기 전부터 가짜 파형을 보여주지 않는다.
- 도움 버튼은 전화 다이얼 화면을 연다. 자동 신고·구조 접수 완료로 표시하지 않는다. 실제 전화는 시험하지 않았다.

## 차량 연동

차량 상태는 보이는 앱 생명주기에서 약 1초 간격으로 갱신한다. 다른 패널에 포커스가 가도 보이는 동안 관측하며 음성은 중단한다. 백그라운드 상시 실행 서비스나 미실행 앱 자동 기동이 구현된 것은 아니다.

CarUxRestrictions를 실제로 구독한다. 초기 연결 실패는 제한 상태로 처리한다. 주행 제한 중에는 질문·체크·차량 제어·설정을 숨기고 읽기 전용 안내만 보여준다. 진행 중 팝업도 닫는다. 에뮬레이터는 android.car 클래스가 부트 클래스 경로에 있으나 동일 이름의 shared library 등록은 없으므로 uses-library는 required=false로 선언했다.

착좌 원시값 2/1에 대한 SDK Boolean 변환 불일치는 해결되지 않았다. 단순 반전하지 않고 앱에서는 null로 취급한다. 문 개방이나 비탑승을 안전지대 도착으로 간주하지 않는다. 후방 충돌 트렁크 보류, 조건 확인, 최신 차량 상태 재검증, 에뮬레이터 debug 제어 제한을 유지한다.

## 검증

- `./scripts/check-android.sh assemblePleosDebugAndroidTest assembleDemoDebugAndroidTest`: 성공. 양 flavor 단위 검사 각 13건, 실패 0. lint 및 APK 빌드 통과.
- Demo UI instrumentation: 6건 통과.
- Pleos UI·음성 instrumentation: 7건 중 6건 통과, Demo 전용 1건 가정 제외. 출력의 `OK (7 tests)`만을 7건 전부 수행한 것으로 해석하지 않는다.
- 실제 Pleos TTS/STT에 합성 PCM을 전달해 도움 요청 응답 → HELP, NEEDS_HELP, 도로 위험 ACTIVE를 검증했다. 이 테스트는 현재 세션의 실제 사람 발화/노트북 마이크 시험이 아니다.
- 라이트·다크, 회전 대신 Activity 재생성의 사건 보존, 전체 확인 행 터치, 후방 충돌 보류, 안내 종료 시 도로 위험 유지, 음성 오류·무응답·오프라인 분리를 검증했다.
- 실제 D와 속도 입력에 CarUxRestrictions 제한이 활성화되고 위험 안내가 유지됨을 확인했다. 기존 콘솔의 주행 물리 계산으로 속도가 시간에 따라 변하므로 고정 20km/h 지속 주행을 주장하지 않는다.

## 기존 콘솔과 추가 도구의 구분

기존 `http://127.0.0.1:8088/`는 **Pleos Connect Virtual Console**이다. 이번 작업에서 만든 `tools/operator-console`은 촬영·앱 시험 보조 도구다. `/recording`은 기존 콘솔 자체를 iframe으로 불러와 실제 에뮬레이터 화면 옆에 표시한다. 원래 콘솔 파일이나 디자인을 수정하지 않았다. `/`의 간이 운영 화면은 별도로 남겼다.

사고 이벤트와 응답 텍스트는 앱 보조 입력이며, 차량 신호는 기존 콘솔 API와 차량 서비스를 거친다. 입력 출처를 마이크/합성 음성/운영자 문장으로 나눈다. 앱 연결이 오래 갱신되지 않거나 앱이 보이지 않으면 보조 입력을 실패 처리한다. 서버는 loopback과 에뮬레이터만 허용한다.

## 남은 기술 범위

에어백 전개 신호 자동 감지, Gleo의 사고 시 자동 호출, 실차 착좌 의미 검증은 완료되지 않았다. 기본 내비 지도 타일이 비어 보이는 기존 환경 문제도 남아 있다. 공공 교통정보 실서비스·실차·실제 신고를 이번 검수 범위에 포함하지 않았다.

## 실제 재현 결과와 전달물

보조 입력·Virtual Console API·ADB UI 테스트를 연결해 고장 → 이동 가능 응답 → 두 확인 행 → 명시적 트렁크 요청 → SDK 열림 확인 → 문 열림·닫힘 → 후속 지원을 자동 재현했다. 별도로 후방 충돌 → 개방 보류·실제 트렁크 닫힘·제어 요청 횟수 0을 확인했다. 마지막으로 접근 차량에서 주행 제한 안내를 확인하고 P·정차로 복구했다. 원본 콘솔은 차량 서비스 상태를 표시하며, 이 영상은 사람이 마우스로 모든 콘솔 버튼을 클릭하는 촬영이 아니라 자동 재현 과정의 동시 화면 기록이다. 합성 음성 인식 검증은 별도 instrumentation 결과이며 이 영상의 응답 입력은 운영자 문장이다.
