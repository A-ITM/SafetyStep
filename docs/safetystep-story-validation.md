# 세이프티스탭 0.4.3 — 사고 차량 시연과 좌석 화면

2026-11-15 KST. 로컬 에뮬레이터 및 로컬 백엔드 검수. 이전 0.4.0 회귀 검증 영상과 구분한다.

## 화면과 문구

기존 Figma의 S4 좌석 배치(`QuiuuWbKFqSNjSHQmOKIOX`, `1:812`)를 읽고 Compose 컴포넌트로 적용했다. Pleos 기본 차량 화면·내비게이션을 유지하고 세이프티스탭은 우측 패널을 사용한다. 기존 라이트·다크 색과 공통 글자·간격·터치 크기를 재사용한다.

- 앱 평상시: **안전운전 하세요 / 오늘도 안전한 이동을 함께할게요.** 상태는 주행 중·정차 중으로 표시한다.
- 외부 콘솔: 인사말 없이 사건 입력, 차량 신호, 앱 반응을 설명한다. 앱의 친근한 문구를 콘솔의 설명 문장에 복제하지 않는다.
- 대피 준비·이동 중·하차 후에 같은 차량 좌석도를 사용한다. 탑승 중은 파란 사람, 관측 중 자리를 비운 좌석은 초록 체크, 처음부터 빈 좌석은 회색으로 표시한다. 운전석 문 열림도 실제 관측에 따라 변한다.
- 좌석 이력은 현재 사건의 관측 범위다. 자리 비움이 안전지대 도착이나 의식·부상 상태를 증명하지 않는다. 처음부터 빈 좌석을 하차로 꾸미지 않는다.
- 동승자가 남아 있으면 이동 지원과 도움 요청을 유지한다. 모든 지원 좌석이 3초 이상 비어 있으면 **안전한 곳에 머무르세요** 화면으로 자동 전환하고 긴급전화·조작 버튼을 숨긴다. 도로 사건은 ACTIVE로 유지한다.
- 후방 충돌은 트렁크 개방을 보류하며 열기 버튼을 표시하지 않는다. 실제 제어 요청 횟수는 0이어야 한다.

## 차량 신호 경로

Vehicle SDK 2.3.2는 착좌 원시값 1/2를 Boolean으로 변환하는 과정에서 의미가 맞지 않았다. Boolean 단순 반전으로 UNKNOWN까지 비탑승으로 만드는 처리는 하지 않았다. SDK의 지원 좌석 조회와 동일한 권한 검사 대상인 Pleos Vehicle Service AIDL 1.1.1을 이용해 변환 전 정수를 읽는 **debug 에뮬레이터 전용 호환 어댑터**를 추가했다. 0·기타·실패는 unknown, 1은 빈자리, 2는 탑승이다. 실차·release에서는 이 호환 경로를 사용하지 않는다.

실제 지원 영역은 1·4·16·32·64의 다섯 좌석이다. 기존 Virtual Console에서 운전석·동승석 착좌를 바꾸고 앱이 VehicleGateway를 통해 다시 관측하는 경로를 검증했다. 콘솔 HTTP 값을 앱 좌석 데이터로 대입하지 않았다. 관측 누락·오래된 값·좌석 영역 축소는 전 좌석 비움 판정을 만들지 않는다.

## 본편과 별도 검증

본편은 사건 없는 주행 → 외부 후방 충돌 재현 → 정차·비상등 → 음성 응답 → 이동 가능 확인 → 후방 충돌 트렁크 보류 → 문 열림 → 운전자 자리 비움·동승자 잔류 → 전 좌석 비움 → 위험 정보 유지로 구성한다. 두 번의 답변은 합성 PCM을 실제 Pleos TTS/STT 경로에 전달한다. 노트북 마이크나 Gleo 자동 기동을 이 촬영으로 검증했다고 주장하지 않는다.

기존 Pleos Virtual Console(8088)은 수정하지 않고 촬영 화면(8790/story)에 함께 표시한다. 외부 충돌 도식은 상황 재현이며 실제 충돌 센서 출력이 아니다. 사건 입력은 debug 운영자 이벤트다. 영상은 무음이며 질문·답변의 SDK 상태를 자막으로 표시한다.

차량 B는 본편 촬영 후 별도로 실행해 A와 동일한 사건 ID를 실제 로컬 HTTP 경로로 수신한다. 반대 방향·다른 도로·지난 사건·오래된 위치의 경고 제외도 확인한다. 현 구현은 서버 전체 목록 조회 후 차량 측 판단이다. 서버의 구간별 수신 등록·선별 전파는 아직 구현하지 않았다.
