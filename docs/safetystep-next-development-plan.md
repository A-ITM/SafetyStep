# 세이프티스탭 후속 개발 계획 — 실행 기준 안내

**현재 개발 작업:** [0.6 프로토타입 구현·검수 계약](safetystep-prototype-v06-plan.md). 사용자의 ‘개발 단계·프로토타입’ 지시에 따라 전면 TEST 흐름을 먼저 구현하며 운영 연동은 별도로 남긴다.

**최신 실행 기준은 [Phase별 실행 계획 1.3](safetystep-execution-plan.md)이다.** 과설계 축소를 반영한 P0~P4, W00~W11 작업 카드, 변경 허용 범위, 검수·인수인계 지시문을 사용한다. 아래 1.1 요약은 검토 경위이며, 여기의 Phase 번호·우선도·재경고·구독 구조를 최신 작업에 그대로 적용하지 않는다.

| P1 | 행동 우선 사고 지원·실제 음성·잔류·신고 화면 |

## 이전 1.1 요약 — 변경 경위 보존

2026-11-17 · 검토 초안 1.1 · 기준 구현 SafetyStep 0.5 / main `78b0fdd`

아래는 [서비스 설계·개발 계획 검토용 1.1](safetystep-service-design-review.md)을 요약한 과거 범위다. 최신 작업 범위와 충돌하면 실행 계획 1.3가 우선한다. 코드·영상·검수 결과가 이미 변경됐다는 의미는 아니다.

## 1. 개발 목표

이동 가능한 탑승자가 위험 장소에 머무는 시간을 줄이고, 접근 차량에 사고 지점 도달 전 경고를 전달한다. 오류 방지와 상태 보존은 이 목적을 달성하기 위한 필수 조건이며, 목적 지표를 대신하지 않는다.

| 요구 | 초기 실험 목표안 | 판정 |
| --- | --- | --- |
| R13 첫 행동 안내 | 지원 시작→발화 시작 2초, 핵심 행동 문장 출력 완료 8초 이내 | 역할·응답·차량 제어·서버 ACK를 기다리지 않음. 실제 음성 출력으로 계측 |
| R14 뒤차 경고 | 수신 및 핵심 경고 음성 출력 시 사고 지점 도달까지 10초 이상 | 실제 주행 기준 남은 거리·시간, 늦은 경고·미경고까지 기록 |
| 조기 주의 | 도움 요청·잔류 가능성이 근거 있는 경우 15초 리드타임 실험안 | 위치·도로 범위·출처·유효기간·정보 최소화와 함께 검수 |

수치는 검증된 안전 기준이 아니라 초기 공학 목표다. 파일럿 후 본 평가 전에 고정하고 결과를 보고 완화해 통과시키지 않는다. 원천 정보 지연이나 늦은 진입으로 목표를 못 맞춘 경우도 전체 위험 접근 건수에서 제외하지 않는다.

## 2. 1.0에서 바뀐 핵심

- **행동 우선**: 첫 조건부 대피 안내 후 도움 요청·이동 불가·특수 위험을 듣는다. ‘말씀하실 수 있나요→역할→이동 가능’이 안내의 선행 단계가 아니다.
- **비상등**: 배포 가능한 읽기→꺼짐/미확인 안내→실제 점등 관측을 먼저 완성한다. 자동 ON은 공식 지원 경로가 검증된 환경에 추가한다.
- **트렁크**: 대피를 막지 않는 P2 요청형 선택 기능이다. 무응답은 생략하고, 개방 동의를 주변 공간의 안전 근거로 바꾸지 않는다.
- **좌석**: 큰 화면 도식보다 잔류 승객 확인 알림과 경고 우선도 판단에 활용한다. 차 밖의 사람이 차 스피커를 듣는다고 가정하지 않는다.
- **전파**: 폴링 주기를 R14에서 역산한다. 공공 정보 1종을 Phase 3의 기본 경고원으로 실제 연동한다.
- **경고 이후**: 속도·브레이크 관측과 추가 접근을 보고 조건부 1회 재경고한다. 감속은 이해 여부의 확정 증거가 아니다.
- **신고 도우미**: 통화 API와 무관하게 노선·방향·대략 위치·연락처를 짧게 제공한다. 위치 확인이나 낭독 때문에 대피를 지연하지 않는다.
- **효과 계측**: 고정 안내 비교 모드·첫 행동/조작 로그는 0.6부터, MAU·유지율 이벤트는 0.7에 포함한다.

## 3. 단계별 개발

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| Phase 0 | D01~D15, 목적 지표, 행동 안내 문장, 비교·계측 계약 | 필수 분기와 파일럿 계획 확정 |
| Phase 1 | 행동 우선 최소 구현, 비상등 읽기 경로, 실제 TTS 계측, SDK 지원표 | N/Y 초기 목표를 본 평가 전에 고정, 미지원 경로 분리 |
| Phase 2 / 0.6 | 예외 청취·잔류 알림·신고 도우미, 최소 본선/시설 판정·보조 시작, 상태/복구, 고정 안내 비교 모드 | R13 및 해당 사고 차량 시험, E01~E02 통과 |
| Phase 3 / 0.7 | 공공 기본 정보 1종, 필수 도로/방향 매칭, 인증·DB·구간 목록·종료, 우선도·재경고, 이용 계측 | R14, 전파·공공·주행 UX 시험, E03~E04 통과. 공공 연동 누락 시 완료 아님 |
| Phase 4 / 0.8 | 복잡 도로 매칭 품질, 약 20명 비교, 선택적 요청형 트렁크 | 오경보·누락·효과와 부정적 결과 보고, 도입 기능의 제어 시험 |
| Phase 5 | 회귀 결과와 목적 지표를 연결한 촬영·문서화 | 영상 주장·실제 로그·미지원 범위 일치 |

공공 API 계약·키·이용 범위 검토는 Phase 1부터 진행한다. 미지원 자동 기동이나 트렁크 때문에 행동 우선·계측·공공 경고를 늦추지 않는다. 담당자·일정은 팀 가용 시간과 외부 답변에 따라 산정한다.

## 5. 경고 지연과 전달 구조

자체 사건의 초기 예산안은 원천 처리 1초 + 업로드 1초 + 서버 0.5초 + 등록/매칭 1초 + 수신 폴링 2초 + 다운로드 0.5초 + 음성 3초 + 여유 1초 = 10초다. 모두 초기 시험 상한안이며 실측이 아니다. 정속 100km/h에서 Y=10초라면 사고 입력 시점 약 556m 이상의 선행거리가 필요하다. 실제 주행의 속도 변화·위치 오차는 별도로 반영한다.

공공 정보는 기관의 확인·공개 지연과 API 갱신/수집 주기를 별도 측정한다. 원천 시각이 없으면 0초로 두지 않는다. 최초부터 늦은 정보로 지나간 차량까지 포함한 전체 지표와, 정보가 충분히 일찍 존재했던 건의 전송 지표를 함께 보고한다.

처음에는 인증된 구간 등록과 서버가 필터한 완전 스냅샷을 사용한다. 전체 사건을 내려준 뒤 앱에서 숨기는 현행 구조를 제거한다. 등록 세대·사건 버전·목록 완전성·제거 사유로 재연결과 역순 응답을 처리한다. Realtime은 지연·권한 회수·유실 복구를 검증한 뒤 도입하며 필수 선행 작업은 아니다.

## 6. 시험과 효과 계측

상세 문서에는 사고 차량 A01~A24, 전파 N01~N23, 효과/이용 계측 E01~E04의 **51개 시험 항목**이 있다. 이 중 선택 기능·Realtime 항목은 해당 기능 도입 시 적용하고 제외 사유를 명시한다. 요구사항 14개, 응답/예외 입력 13개, 팀 결정 15개와 연결한다.

비교 실험은 같은 정보·시나리오의 고정 안내 모드와 행동 우선 모드를 사용하고 순서 효과를 통제한다. 안전 구역 도달은 평가자 관측 등으로 기록하며 좌석 비움과 구분한다. 원음은 기본 저장하지 않고 실험 입력·로그·영상 편집을 구분한다.

MAU는 해당 월 수신 기능을 켜고 실제 주행한 고유 차량 수다. 설치 수나 경고 수신 횟수가 아니다. 유지율은 첫 활성 주행 뒤 28~34일의 재활성 주행이며, 관측 기간이 부족하면 결과를 확정하지 않는다. 설치 100대·MAU 60~80대는 기획서의 운영 가정으로만 남긴다.

## 7. 미확정 항목과 경계

D13 행동 우선 대화·N, D14 경고 예산·Y, D15 우선도 기준을 본 평가 전에 확정한다. D02 요청형 트렁크는 사용자의 개방 의사와 필요한 안전 근거를 분리한다. 파생 우선도도 위치·사건과 결합하면 민감한 상태를 추론할 수 있어 개인정보가 없다고 단정하지 않는다.

SDK 에어백·Gleo 선제 기동·배포 비상등 권한은 현재 입증된 범위를 넘어서 주장하지 않는다. 사건 만료·통신 단절·좌석 비움은 도로 위험 종료가 아니다. 종료 권한과 불명 사건 게시 정책은 상세 문서 D05/D07을 따른다. 앱 코드 변경·실차 제어·긴급 신고·실도로 효과 입증은 이번 문서 개정으로 완료되지 않는다.
