# SafetyStep 0.7 — 사고 맥락과 GPS 위치 공유 검수

2026-11-17. 개발 프로토타입의 전면 실행 범위다. 실제 사고·실차·운전자 효과 시험이 아니다.

## 변경과 판정 기준

일반 정차는 사고가 아니다. 사고 입력이 있을 때 `사고 후 안전 지원` 맥락을 유지하고, 현재 차량 속도로 읽는 `차량 상태`와 `사고 위치 공유`를 따로 표시한다. 정차 확인이나 음성 응답을 서버 등록 조건으로 사용하지 않는다. 공유에는 사전 동의와 유효한 위치가 필요하다.

GPS를 우선 읽고 사용할 수 없으면 Pleos NaviHelper 위치를 출처 그대로 사용한다. 주소를 다른 GPS 좌표에 합성하지 않는다. 사고 위치는 사고 시점 주변에 받은 좌표 한 번으로 고정한다. 수신 차량은 자기 현재 위·경도로 주변 사건을 조회한다. 도로·방향을 맞추지 않으므로 화면은 `주변 사고`, `약 N m`, `직선 거리`라고 표시한다. [공통 계약](contracts/accident-location-v07.md)을 따른다.

## 검수와 수정

- 독립 검토에서 위치 변경 뒤 이전 조회 결과가 최신으로 남는 문제를 수정했다. 좌표가 바뀌면 확인 상태를 무효화하고 해당 위치로 받은 응답만 적용한다.
- 기존 고장 지원 중 새 사고 입력을 받으면 새 ID와 사고 시각으로 전환한다. 이미 받은 이동 불가·도움 요청은 전환 후에도 유지한다. 충돌 방향을 모름으로 변경해도 사고 자체를 정차 사건으로 낮추지 않는다.
- 이전 신고 위치 요청이 새 사고 좌표를 덮어쓰지 않도록 취소와 세션 검사를 추가했다.
- 공유 동의·연결 상태가 꺼지면 업로드 작업을 취소하고 실제 전송 직전에도 상태를 확인한다. 이미 서버로 보낸 요청은 되돌릴 수 없으므로 원본 outbox를 유지해 ACK 유실에 대비한다.
- GPS는 수신 시각뿐 아니라 제공된 원래 측위 시각의 신선도도 검사한다. 주소 길이, JSON 필드, ACK 내용과 버전을 Android와 서버에서 맞췄다.
- 화면의 불필요한 수신 미확인 설명은 상세창으로 옮겼다. 등록 완료를 다른 차량의 안내 완료로 표현하지 않는다.

## 실제 에뮬레이터 연속 확인

Pleos Connect 2.1, Android 14 arm64, `emulator-5554`, 사용자 10. 원래 차량 상태·내비게이션 화면 옆 841×1210px 우측 패널에서 확인했다. 두 앱 소유자 A(pleos)와 B(demo)를 한 AVD에서 순차 실행했다. GPS 좌표는 `adb emu geo fix`로 공급하고 앱은 Android LocationManager API로 읽었다. 에뮬레이터의 `isMock=false` 값을 실제 도로 측위의 증거로 해석하지 않는다.

| 흐름 | 관측 결과 |
| --- | --- |
| 사고 입력 없는 일반 정차 | 사고 세션 없음, 사고 공유 IDLE, 평상시 화면 유지 |
| 후방 충돌 시험 입력·90km/h | 사고 맥락과 이동 중 표시. 응답 없이 사고 위치 고정·등록 대기 |
| 정지·통신 보류 | 정지 확인과 서버 등록 대기 동시 표시 |
| 연결 복원 | 같은 사고 ID가 JSON 서버에 저장되고 등록 완료로 전환 |
| 운전석 비움·동승석 잔류 | 실제 콘솔 좌석 신호에 따라 좌석도 갱신 |
| 이동 불가 시험 문장 | 도움 화면 우선, 신고 참고 위치와 전화 동작 표시. 마이크 시험은 아님 |
| 사고 차량 위치 이동 | 사고 좌표는 그대로이고 차량 현재 좌표만 변경 |
| A 사고 → B 수신 | 같은 사건 `4c7add7a-feb8-4d95-9e5e-0bf5131794f8` 수신, 직선거리 300.04m. UI는 약 301m |
| 수신 통신 단절 | 기존 사고를 최신 상태 미확인으로 표시 |
| 1km 밖 이동 | 새 위치의 서버 빈 목록을 확인한 뒤 해당 차량의 알림 제거 |
| 서버 재시작 | 디스크의 같은 사건 복원, 원래 요청 재전송에 duplicate ACK |
| 추가 B 사고 → A 주행 경고 | 사건 `3e8d5acf-932e-4556-b5c7-cf16710910e6`, Pleos 90km/h 주행 제한 상태에서 표시와 TTS 완료 확인 |
| 시험 관리자 종료 | 해당 사건 RESOLVED/version2 수신 후 알림 제거 |

추가 주행 시험에서 제한 상태 관측은 AVD elapsed 497926ms, 실제 `geo_warning_voice_complete` 콜백은 501959ms였다. 이는 그 화면 상태에서 음성이 완료됐다는 증거이며, 사고 감지부터의 지연이나 운전자 반응 효과를 뜻하지 않는다. demo의 음성 미지원은 음성 성공으로 세지 않았다.

밝은/어두운 테마로 10개 상태, 원본 PNG 20장과 대응 JSON을 로컬에 저장했다. 비교용 HTML은 원본의 우측 패널을 표시하며, 원본 전체 화면으로 이동할 수 있다. 저장소에는 스크린샷·좌표 로그·APK를 포함하지 않는다.

## 재현

기존 JDK 17과 `~/.gradle`을 사용한다.

```sh
./scripts/check-android.sh assembleDemoDebugAndroidTest assemblePleosDebugAndroidTest
# 별도 터미널, 다른 시험과 섞이지 않는 새 파일을 사용한다.
./scripts/run-prototype-server.sh --data=output/v07-manual-review/accidents.json
# 두 debug APK를 해당 AVD에 설치한 뒤 실행한다.
python3 scripts/verify-accident-location-v07.py --serial emulator-5554 --output output/v07-manual-review/screens
```

연속 확인 스크립트는 지정 AVD의 GPS·속도·기어·좌석·문 신호와 두 앱의 설정을 바꾸고 위치 권한을 허용한다. 종료 시 속도 0/P로 복구한다. 실제 휴대폰·차량에는 실행하지 않는다. 신규 서버 자료로 실행해야 다른 시험의 사건이 결과에 섞이지 않는다. 추가 주행 음성과 서버 재시작·종료는 위 기록의 별도 통제 시험이다.

## 남은 범위

- 서버는 로컬 파일을 영속화하는 프로토타입이다. 운영 Supabase 배포, 사용자 인증과 다수 차량의 실제 인터넷 연결은 하지 않았다.
- 내비게이션 앱 위에 사고 마커를 그리거나 도로·진행 방향을 판별하지 않는다. 반경 안 다른 도로의 사고도 받을 수 있다.
- GPS→Navi 대체와 메타데이터 처리는 코드·단위 시험에서 확인했다. 이번 새 연속 시험은 GPS 경로이며, 실차 Navi 데이터의 신선도를 검증한 것은 아니다.
- 자동 사고 감지·백그라운드 자동 기동·공공 정보·차량 자동 제어는 이번 변경의 결과로 주장하지 않는다. 사고 시험 입력은 기존 에뮬레이터 전용 경로다.
- 앱과 서버 저장소는 각각 최대 500건의 개발용 보관 한도를 갖는다. 만료를 사건 종료나 자동 삭제로 취급하지 않는다.
