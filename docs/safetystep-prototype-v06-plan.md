# SafetyStep 0.6 개발 프로토타입 — 구현 범위와 검수 계약

2026-11-17 · 기준 main `78b0fdd` · 상태: 문서 검수 5회 완료·지적 반영, 구현 착수 가능

## 1. 우선순위와 이번 완료의 의미

사용자의 최신 지시는 **개발 단계의 프로토타입을 5회 문서 검수 후 구현하고 커밋·PR·리뷰·머지까지 수행**하는 것이다. 이 문서가 이번 PR의 실행 범위다. 1.3 계획은 장기 설계와 원칙의 근거이며 운영 Auth/DB·공공 API·비전면 실행·연구 실험 전체를 이번 완료의 선행 조건으로 삼지 않는다.

구현자는 gpt-6.1-sol xhigh, 주관자는 root다. 코드 작성 전에 문서 검수 5개 기록과 수정 반영을 완료한다. root가 계약·공통 파일 변경·최종 검증·GitHub 작업을 조율한다. 작업별 지정 파일 밖 수정은 다른 담당자와 조율하며, 일반적인 구현·검증마다 사용자 승인을 다시 묻지 않는다.

**환경:** 전면 실행 중인 Pleos 2.1 AVD의 `pleosDebug`와 명시적 샘플 `demoDebug`, 기존 loopback Deno HTTP 서버. 실제 차량·연결된 개인 휴대폰에는 설치하거나 제어하지 않는다. 신규 JDK/Gradle home/클라우드 서비스는 만들지 않는다.

## 2. 구현할 세 흐름

1. **사고/고장 대응:** 명시적 시험 사고/고장 입력 + 관측된 정차 → 첫 행동 음성 → 도움 예외·잔류 좌석 확인·신고 정보. 역할·이동 가능 질문의 답을 먼저 요구하지 않는다. 비상등은 읽어서 안내하며 자동 쓰기와 트렁크 제어를 정상 흐름에서 호출하지 않는다.
2. **응답 없는 정차 관측:** 사전 공유 동의 + 검증된 TEST 본선/갓길 위치 + 연속 정차 → STOPPED_VEHICLE 한 건 공유. 응답·비상등 ON·지원 세션 생성과 독립이다. 후보만으로 대피 지시나 ACCIDENT를 만들지 않는다. 후속 도움 응답이 와도 정차 사건 ID를 바꾸지 않는다.
3. **접근 차량:** 정차 중 수신 ON → 주행 중 관련 사건만 서버에서 수신 → 실제 거리와 화면·가능한 음성 경고. 저속 정차 관측은 첫 음성만 보류하고 카드 유지. 가속/접근하면 미발화 경고를 다시 평가한다. 이탈/통신 오류/TTL은 사건 해소가 아니다.

고장·단순 ‘도와줘’는 ACCIDENT 유형의 근거가 아니다. 새로운 공유 사건을 만들 때 명시적 사고 입력은 ACCIDENT, 고장/정차 관측은 STOPPED_VEHICLE로 다룬다. 같은 연속 정차에 이미 ACTIVE 정차 사건이 있으면 뒤늦은 사고/도움 보고는 로컬 지원에 반영하고 기존 공유 ID·유형을 유지한다. 유형은 생성 뒤 바꾸지 않는다. 정말 별개 사고를 확인한 경우에만 별도 새 사건 입력으로 생성하며 늦은 답변으로 중복 생성하지 않는다.

## 3. 이번에 넣지 않는 것

- 운영 Supabase Auth/DB, public feed 실수집, 정밀 실제 도로 매칭·전국 도로, 비전면/강제 종료 자동 기동.
- 감속 기반 두 번째 경고, 출처가 다른 실제 사건 자동 병합, 20명 연구·MAU/코호트 도구, 새 디자인 체계.
- 트렁크 요청/자동 제어, 정상 지원 경로의 비상등 자동 쓰기, 자동 긴급 신고.
- 촬영·영상 편집. 구현과 재현·검수 산출물을 먼저 완료한다.

위 항목은 미구현/미검증으로 명시한다. TEST를 live로 표시하지 않는다. 자체/공공 선행 시간 Δ는 실제 두 소스가 없는 이번 버전에서 미측정이다. 현재 공개 A/B 문자열은 시험 식별자이며 실제 인증이 아니다.

## 4. 작은 동결 계약

### 4.1 위치·정차·음성

단위는 ms UTC, 거리 m, 속도 m/s. 정책 경과 시간은 단조 시계를 사용한다. TEST 도로에서 direction별 meters는 진행 방향으로 증가한다. 지원 도로는 `test-highway`, 비교 제외 도로는 `parallel-highway`; `east/west`, 0~10,000m 범위다. 시설은 명시적 TEST `MAINLINE / SHOULDER / FACILITY / UNKNOWN` 입력이다. 이 값을 실제 GPS 도로 판정으로 소개하지 않는다.

정차 공유의 초기 실험값은 유효 위치/속도(15초 이내), `|speed| ≤ 0.5m/s` 연속 5초, 본선/갓길, 동의 ON이다. 기어 P만 요구하지 않는다. 속도·위치 불명, 시설, 동의 OFF면 생성하지 않는다. 최초 정차 시각을 따로 보존한다. 같은 연속 정차는 ID 하나다. 재출발은 `speed ≥ 2m/s` 연속 3초의 새 관측으로 자기 STOPPED_VEHICLE만 철회한다. 불명/오프라인/TTL/단순 구간 이탈은 재출발 증거가 아니다. 이는 실도로 안전 임계값이 아닌 통제 시험값이다.

행동 첫 문장 기본안: “주변을 살피고, 안전하게 내릴 수 있으면 가드레일 밖 등 안전한 곳으로 이동하세요.” 도움 필요가 이미 알려졌으면 “무리하게 움직이지 마세요. 가능한 방법으로 도움을 요청하세요.”를 우선한다. 비상등 꺼짐/불명 안내는 짧게 별도로 하며 실제 켜짐 전 성공 발화는 없다. 트렁크 필수 안내는 없다. 공식 원문과 앱용 축약 차이는 1.3 검토 문서를 따른다.

첫 문장 TTS가 완료된 뒤 예외 청취 한 번을 시작한다. ‘네’는 응답 사실이며 이동 가능 판정이 아니다. ‘도와줘/못 움직여요’·동승자 보고·부정·불확실·STT 실패·무음을 구분한다. 이미 지원 중일 때 늦은 도움 입력도 수용한다. TTS 중 동시 마이크 청취를 지원한다고 가정하지 않는다. 청취 재시도 UI는 보조 수단이며 대피 진행의 필수 조작이 아니다. 오디오/화면 중단 뒤 저장된 도움은 유지하고 오래된 콜백은 버린다.

### 4.2 사건과 HTTP

기존 `/prototype/incidents`의 소규모 계약을 확장한다. Android와 서버가 같은 fixture를 사용한다. 정확한 필드·경로·오류·적용 순서는 [동결 계약](contracts/prototype-v06.md)과 [공용 TEST fixture](contracts/fixtures/prototype-v06.json)에 정의했다. 이 절의 요약과 세부 wire 표현이 다르면 동결 계약을 따른다.

- 사건은 기존 필드에 `eventType: ACCIDENT | STOPPED_VEHICLE`, `status: ACTIVE | RETRACTED | RESOLVED`를 둔다. `simulation:true`만 허용한다. 공유 payload에는 응답·도움·좌석·원음이 없다.
- 출처는 기존 시험/SDK/Gleo 입력과 `STOP_OBSERVATION`을 구분한다. SDK 이름이 있어도 입력이 TEST인 사실을 숨기지 않는다.
- ID/관측/위치/유형은 멱등성과 버전으로 검증한다. 동일 버전·동일 payload 재시도는 같은 ACK, 다른 payload/낮은 버전은 충돌이다. 재시도는 신선도를 늘리지 않는다.
- 정차 철회에는 새 재출발 관측(시각·속도·지속시간)이 필요하다. owner만 자기 STOPPED_VEHICLE을 철회할 수 있다. ACCIDENT 해소는 명시적 loopback 시험 관리자 경로이며 일반 A/B 요청으로 해결하지 않는다.
- GET은 `requestId`, 현재 TEST 도로·방향·meters·observedAt와 선택적 speedMps를 받는다. 속도 불명은 생략하며 조회·카드가 가능하다. 지원 도로/방향/범위/현재성을 서버가 검사한다. 잘못된 위치는 오류이며 성공한 빈 목록이 아니다.
- 서버는 같은 도로·방향의 전방 1,000m 안에 있는 관련 사건만 반환한다. 반대 방향·평행 도로·통과·범위 밖의 상세 payload는 반환하지 않는다. 종료/철회도 같은 범위에서 ID별 처리한다.
- 응답은 `requestId`, `epoch`, `scopeKey`, `scopeVersion:1`, `serverNow`, `complete:true`, `sourceHealth:TEST_ONLY`, `events`를 보존한다. 페이지를 잘라 완전 목록으로 가장하지 않는다.
- TTL 만료는 ACTIVE/STALE이며 자동 종료가 아니다. 메모리 서버 재시작은 epoch 변경/자료 초기화로 명시하고 그 결과를 ‘도로 안전’으로 표시하지 않는다. 영속 DB를 구현했다고 주장하지 않는다.
- 앱은 HTTP/파싱/완전성/이전 구간/낮은 버전 오류를 구분한다. 완전 스냅샷은 원자적으로 적용하고 옛 구간 응답을 폐기한다. 업로드와 수신은 각각 단일 요청 루프로 분리한다. 영구 거절 outbox는 이유와 함께 격리하고 수신을 막지 않는다.

### 4.3 수신과 표시

공유 동의와 수신 설정은 별개다. 수신 최초 OFF, 설정 저장/다음 실행 복원. 실제 상태는 `OFF / ACTIVE / PAUSED / UNAVAILABLE`. 전면에서만 가능하므로 이탈 때 PAUSED. 네트워크/위치 불명은 ACTIVE로 가장하지 않는다. 사용자 화면에는 프로토콜 설명 대신 상태와 필요한 행동을 표시하고 TEST 입력은 개발 도구/표시에서 식별한다.

서버 제공 범위는 1,000m, 앱의 첫 경고 범위는 `speed × 20초`를 200~1,000m로 제한하는 기존 실험 정책을 사용한다. 속도 불명일 때는 1,000m 범위를 사용하고 저속 억제를 적용하지 않는다. STOPPED_VEHICLE에서 유효 속도 ≤3m/s가 3초 지속되고 거리가 100m 초과일 때 첫 음성만 보류한다. 거리 ≤100m 또는 속도 >3m/s이면 미발화 경고를 재평가한다. ACCIDENT에는 이 저속 예외를 적용하지 않는다.

동일 사건 ID 재수신의 중복 최초 음성을 방지한다. 실제 음성 완료만 ‘발화 완료’로 기록하며 실패·중단은 별도다. 재시작 범위의 중복 이력도 보존한다. 다른 출처의 별개 ID가 같은 실제 위험을 뜻하는지 자동 병합하지 않는다. 내 차량 지원과 접근 경고가 겹치면 자체 지원이 우선한다.

좌석 불명·미지원·오래됨은 비움이 아니다. 도움 상태는 도로 사건 RESOLVED/RETRACTED 뒤에도 유지한다. 잔류 알림은 관측 좌석을 대상으로 하며 물체/사람을 확정하지 않는다. 현재 상태와 신고 위치를 한 화면에 두고 ‘다음’ 진행을 요구하지 않는다.

### 4.4 신고 위치·계측

NaviHelper 3.0.5의 현재 위치 API를 별도 작은 gateway로 연결한다. 좌표·address·heading·응답 시각을 읽되 provider fix 시각/정확도가 없으면 모른다고 둔다. 응답 시각을 실제 측위 시각으로 꾸미지 않는다. heading→도로 상하행 변환은 하지 않는다. 실제 API 응답/미지원은 구분하며 도로 전파에는 여전히 TEST 위치만 사용한다. demo는 명시적 샘플/미지원이다.

로컬 JSONL 계측은 입력 출처·ID·UTC/단조 시각·상태·관측/수신/실제 TTS 완료를 구분한다. N(지원 입력→음성 시작/완료), N_total(최초 근거→완료), H(최초 정차→접근 수신/음성 완료), Y(모의 통과 시각−경고 시각)를 계산할 수 있어야 한다. TEST position 입력을 실제로 진행시켜 사고 위치를 통과한 시각으로 Y를 구한다. 고정 거리/속도의 예상 TTC는 측정 Y가 아니다. H는 지원 세션 없이 생성된 사건 ID도 연결한다. 출력 불가/미시작/억제를 성공으로 세지 않는다. 원음/전체 대화 원문은 계측 파일에 기록하지 않는다.

| 작업 | 소유 파일 | 결과 |

| 주관·계약·문서 검수 | 이 문서, 계약 문서, README/최종 검수, Git/PR | 다섯 검수·동결 계약·통합 판정 |
| B: 서버 | `supabase/functions/_shared/prototype*`, `supabase/local/`, 서버 계약 fixture/tests | 유형/철회·범위 스냅샷·실제 HTTP 시험 |

| C: 음성/위치/UI | `speech/`, 신규 위치 gateway+flavor factory, `ui/`, 관련 tests | 첫 음성/청취 분리·실제 위치·패널/수신 화면 |
| 통합 QA | 지정된 테스트/스크립트, 검수 문서 | 두 flavor 검사·에뮬레이터 연속 재현·PR 리뷰 |

A가 먼저 UI 상태/호출 인터페이스를 C에게 알리고 공통 VM 파일은 A만 수정한다. C의 위치/음성 인터페이스를 A가 연결한다. B와 A는 계약 JSON을 함께 읽으며 API 변경은 주관자에게 알린다. 같은 checkout에서 지정 파일만 수정하며 각 담당자는 커밋하지 않는다. root가 작업 단위 diff를 검토해 커밋한다. Gradle/에뮬레이터/마이크 소유자는 동시에 한 명이다.

## 6. 프로토타입 통과 기준

- 문서 검수 5회와 발견 사항의 반영/보류 근거 완료.
- 정상 사고 입력 뒤 사용자 응답 전에 첫 행동 안내; 도움 예외·잔류·도로 종료 후 지원 보존; 정상 제어 명령 0회.
- 무응답·비상등 OFF·D/N 정차에서도 공유 조건 충족 시 하나의 정차 사건 전송. 시설·불명·동의 OFF 제외. 재출발 철회가 다른 사건을 지우지 않음.
- 서버 필터·버전·오류/빈/STALE/초기화·outbox 독립 수신 시험. 평상시 수신 상태와 실제 실행 일치.
- 두 테마·우측 패널·주행 경고의 화면 검수. 거리 하드코딩·샘플을 실측으로 위장하는 표현 제거.
- `./scripts/check-android.sh`, Deno fmt/lint/check/test, 변경 계약 smoke 통과. 에뮬레이터 대상만 명시해 관련 계측/연속 재현을 수행한다.
