# SafetyStep 인포테인먼트 UI·흐름 개선

2026-11-17 · 기준 0.6 (`d3bfcc2`) · 범위: Android 표시·조작 흐름

## 판단과 변경 기준

기존 구현은 큰 제목·음성 버튼·좌석도·중복 상태·상세 위치가 세로로 쌓여 우측 패널에서 스크롤을 요구했다. 정상 화면의 두 시작 버튼과 반복된 수신 설명은 수동 조작을 주 흐름처럼 보이게 했다. 차량 상태·내비게이션은 Pleos의 원래 영역을 사용하고, 세이프티스탭은 우측 앱 패널에서 상황에 필요한 정보만 우선한다.

기존 [Figma 스토리보드](https://www.figma.com/design/QuiuuWbKFqSNjSHQmOKIOX/Untitled--Copy-?node-id=1-2)의 영역 분리·좌석도·상태 표시를 참고했다. 이전 질문 우선 흐름과 미검증 자동 기동 표현은 0.6 계약을 따라 사용하지 않는다. 기존 Compose 컴포넌트와 밝은/어두운 테마를 유지한다.

[Android Design for Driving](https://developer.android.com/design/ui/cars/guides/foundations/design-principles)은 짧은 작업, 음성 상태 표시, 주행 상황에 맞는 화면을 권장한다. [Visual principles](https://developers.google.com/cars/design/design-foundations/visual-principles?hl=en)의 가독성·터치 간격을 참고하여 기존 최소 80dp 터치 영역과 24dp 간격을 적용한다. 이는 설계 참고 기준이며 Pleos 인증 또는 실제 운전자 주의 분산 시험을 통과했다는 뜻은 아니다.

## 화면별 흐름

### 이미지에서 가져온 디자인 시스템

참고 이미지를 장식용으로만 쓰지 않고 아래 역할을 공통 토큰·컴포넌트에 연결한다. 이름이 바뀐 세이프티스탭과 현재 0.6 기능에 맞춰 문구와 정보 밀도를 조정한다.

| 요소 | 공통 규칙 | 구현 위치 |
| --- | --- | --- |
| 바탕·표면 | 이미지의 네이비 패널 `#171F34`, 안쪽 표면 `#232E45`. 밝은 모드는 흰 패널·옅은 회색 표면 | `SafetyStepTheme.kt` |
| 의미 색상 | 파랑은 정보·기본 동작·좌석 관측, 민트는 확인된 관측 변화, 호박색은 위험·확인 필요, 빨강은 119 | `SafetyColors` |
| 글자 위계 | 핵심 제목 42/54sp, 본문 26/36, 상태 24/32, 동작 28/36, 부가 정보 20/28. 경고 거리만 72/80 | `SafetyStepTokens.kt` |

Figma의 42dot Sans는 앱에 포함되어 있지 않아 현재 시스템 한글 글꼴을 유지한다. 이미지의 작은 축소 글자 크기를 그대로 복사하지 않고 실제 앱 패널에서 읽히는 크기로 적용한다. 색만으로 상태를 구분하지 않고 글자·좌석 표시를 함께 제공한다.

### 상황에 따른 구성

| 상태 | 먼저 보일 정보 | 선택 조작 |
| --- | --- | --- |
| 평상시 정차 | 짧은 인사·실제 수신 상태. 수신한 위험이 있으면 위험 정보 우선 | 수신 설정, 사고·고장 도움받기 한 곳 |
| 주행 | 선택한 한 사건의 종류·거리·신선도·짧은 행동 안내 | 조작·스크롤 없음 |
| 정차 후 지원 | 첫 행동 문장·현재 음성 상태·관측 좌석·비상등 | 이동이 어려울 때 도움 요청. 첫 안내의 선행 조건 아님 |
| 도움 필요 | 도움 안내·신고 참고 위치 | 고정된 119 전화 열기. 이미 기록한 도움 요청을 다시 요구하지 않음 |
| 관측 좌석 비움 | 좌석 관측·안전한 곳에 머무를 안내 | 별도 도움 상태가 없으면 전화·도움 버튼 숨김 |

- 설정·진단·상세 표시 중 새 지원 또는 도움 필요 상태가 들어오면 해당 안내가 가려지지 않게 한다.
- 위치의 상세 시각·정확도·새로고침은 펼쳐 보되, 샘플과 위치 확인의 한계는 요약에서도 숨기지 않는다.
- 개발용 원시 오류·전송 내부 상태는 진단으로 모으고, 기본 화면에는 연결·위치 확인 필요 등 짧고 사실에 맞는 상태를 표시한다.
- 좌석 감지를 사람 수·의식 상태·안전지대 도착으로 바꾸지 않는다. 도움 필요 상태는 좌석 비움이나 도로 사건 종료보다 우선한다.
- 수신 ON과 정상 수신은 구분한다. 한 경고의 제목과 다른 경고의 신선도를 섞지 않는다.

## 이번 변경의 경계

서버·사건 판정·공유 조건·수신 계약·TTS/STT 실행 순서·차량 제어는 변경하지 않는다. 일반 도움 진입은 기존 정차 차량 지원 의미를 유지한다. 실제 사고 자동 기동·운영 API를 새로 구현한 것으로 표현하지 않는다.

실제 화면 검수에서 새 버튼 문구인 “움직이기 어려워요”를 동일하게 입력하면 기존 음성 판정은 미확인으로 남는 것을 발견했다. 화면과 음성의 표현을 맞추기 위해 직접적인 이동 어려움 발화만 도움 요청으로 인식하도록 좁게 보완하고 부정·추측 표현은 미확인으로 유지한다. 새로운 음성 엔진이나 의료적 판정을 도입하지 않는다.

## 검수 항목

- 841×1210dp 우측 패널과 600×900dp 축소 영역에서 핵심 안내·도움 버튼·신고 위치 가림 여부.
- 밝은/어두운 테마, 긴 주소, 음성 오류, 미확인 좌석, 동승석 잔류, 좌석 비움과 도움 필요 동시 상태.
- 주행 화면의 버튼·스크롤 부재, 선택 사건과 신선도 일치, 설정 중 지원 진입.
- 기존 상태 보존·정상 흐름 차량 제어 0회 회귀 검사.
- Android 두 flavor 단위 시험·lint·APK 및 실제 에뮬레이터 UI 검사.

검수 중 두 가지 시험 입력 문제를 바로잡았다. Pleos의 기본 주행 제한값을 정차 화면 시험에도 적용하던 fixture를 명시적인 정차 상태로 고쳤다. ADB 원격 셸이 공백 포함 발화를 잘라 보내던 문제는 `verify-prototype-v06.py`에서 셸 인자를 이스케이프하여 수정했다. 별도로 앱의 직접적인 이동 어려움 문장 두 가지를 인식하고, 부정·추측 문장은 미확인으로 남기는 회귀 시험을 추가했다. 최종 앱 APK로 두 flavor UI 검사와 실제 분할 화면 흐름을 재확인했다.

로그·캡처는 로컬 `output/infotainment-ui/`에 보관한다. `android-check.log`, `device/demo-ui.log`, `device/pleos-ui.log`, `visual/visual-result.json`, `visual/01`~`09` 캡처가 최종 결과다. 이 경로는 Git 추적 대상이 아니다.

이번 음성 판정 연결 시험은 발화 텍스트를 주입한 검사이며 노트북 마이크 재시험은 아니다. 주행 경고의 도로 위치는 명시적인 TEST 입력이다. 실제 센서 탑승자 식별, 실차 안전성, 백그라운드 자동 기동이나 운영 공공 API 연동을 검증한 것으로 확장하지 않는다.
